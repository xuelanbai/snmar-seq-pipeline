# snMAR-seq pipeline v2026.10.16 发布说明

## 1. 发布定位

这是 2607 snMAR-seq 人/猪混合细胞项目的**代码整理发布版**，用于：

1. 固定本批数据实际采用的正式生产流程；
2. 保留已经运行的方法审计与探索性分析；
3. 将尚未成为最终结果的方法试验与正式流程清楚隔离；
4. 为后续修改提供可测试、可追溯的 Git 基线。

版本号采用日期快照 `v2026.10.16`。`VERSION`、Git tag 和 GitHub Release 应保持一致。

## 2. 最终主流程

正式主流程为步骤 01–110：

```text
DNA/RNA raw FASTQ
  -> 严格 barcode 拆分
  -> DNA paired-end fastp / RNA R1-only fastp
  -> human+pig 联合参考 mapping
  -> DNA CB-aware PCR 去重 / RNA reverse GeneFull exact-UMI
  -> DNA WCG/GCH 单碱基矩阵 / RNA gene-by-cell 矩阵
  -> BigWig、单细胞 QC、100 kb 矩阵和批次汇总
  -> DNA 100 kb UMAP 与 mapping-derived GM12878/PK15 审计
```

其中 WCG 表示内源甲基化信号，GCH 表示 GpC 标记开放性信号，GCG 为重叠歧义位点并从两类主信号排除。

## 3. 分析状态边界

| 步骤 | 发布状态 | 可否作为最终流程引用 |
|---|---|---|
| 01–86 | 已完成并汇总验证 | 可以 |
| 87–110 | 已完成并形成下游 QC/UMAP 结果 | 可以，但 UMAP 必须附解释边界 |
| 111–121 | 已运行的 RNA salvage | 只能作为探索性结果 |
| 122–134 | 已运行的 TSS±1.5 kb UMAP | 只能作为阴性/不清晰的探索性结果 |
| 135–146 | 同源 100 kb 方法试验 | 不能标成已验证最终结果 |
| 147–154 | promoter 敏感性和二维对照 | 不能标成已验证最终结果 |

### DNA UMAP 解释边界

- reference-aware 100 kb 特征同时包含 human/pig 参考序列差异与 WCG/GCH 比例信息；
- mapping-derived GM12878/PK15 标签来自同一批 DNA 的参考物种覆盖比例，只是内部一致性审计；
- 若要检验“仅由甲基化模式分群”，应优先使用严格同源特征，并将物种标签只用于降维后的验证。

### RNA 解释边界

- RNA strict10 拆分率较低，且存在低深度、非特异性捕获和潜在二次 RT 串扰问题；
- exon-supported salvage 能生成探索性矩阵，但不能替代高质量标准表达矩阵；
- RNA 物种标签应依据唯一比对、exon/gene 支持和 exact UMI 分层审计，不能只看任意 mapping reads。

## 4. 代码布局

- `03_scripts/01_demultiplex`：DNA 拆分；
- `03_scripts/02_rna_demultiplex`：RNA strict10 拆分；
- `03_scripts/03_mapping`：fastp、联合参考、STAR/BWA；
- `03_scripts/04_postmapping`：去重、表达/甲基化矩阵、BigWig、QC；
- `03_scripts/05_downstream_analysis`：100 kb、跨孔汇总、细胞 QC、RNA/DNA UMAP、promoter 与同源方法；
- `tests`：无需真实 BAM/FASTQ 的回归测试；
- `docs`：逐阶段说明和方法边界。

完整输入输出索引见 `docs/分析流程与代码说明.md`。

## 6. 发布内容与排除项

GitHub 和独立 clean copy 仅包含 Git 跟踪的源代码、小型索引、配置示例、测试和文档。以下内容不进入发布包：

- FASTQ、BAM/BAI、HDF5、MatrixMarket、BigWig、bedGraph；
- `08_qc_summary` 结果、集群日志、渲染后的临时 job；
- `__pycache__`、本地环境文件和编辑器缓存；
- PPT、Word、PDF、PNG 等汇报材料。

## 7. 推荐使用方式

1. 从 Git tag `v2026.10.16` 获取固定代码；
2. 复制 `config/project.env.example` 为 `config/project.env`；
3. 修改项目路径和环境名，不直接改写源代码中的发布记录；
4. 按步骤编号运行，每个阶段先 summary/validation 再进入下一阶段；
5. 对探索性脚本另建分支或新版本，不覆盖本 tag。
