# snMAR-seq 分析流程与代码说明

本文是本仓库的主追溯文档，按照实际分析顺序记录每个代码文件的位置、主要输入和主要产出。所有路径均相对于 GitHub 仓库根目录；数据路径均相对于集群项目根目录 `$PROJECT`。

## 1. 流程总览

```text
DNA/RNA raw FASTQ
  -> barcode QC 与严格拆分
  -> DNA paired-end fastp / RNA R1-only fastp
  -> 人+猪带前缀联合参考
  -> DNA BWA-MEM / RNA single-end STAR
  -> DNA CB-aware PCR 去重 / RNA reverse GeneFull exact-UMI
  -> DNA WCG/GCH 单胞嘧啶矩阵 / RNA gene-by-cell 矩阵
  -> DNA pseudo-bulk BigWig、单细胞覆盖 QC 和完整矩阵封装
```

关键数据目录：

| 项目目录 | 内容 |
|---|---|
| `00raw_data/` | 原始 DNA/RNA FASTQ |
| `02_reference/` | 人+猪联合参考、STAR/BWA 索引 |
| `04_fastq_split/` | 拆分后 FASTQ |
| `05_fastp/` | 清洗后 FASTQ |
| `06_mapping/` | STAR/BWA BAM |
| `07_postmapping/` | 去重 BAM、表达矩阵、甲基化矩阵和轨迹 |
| `08_qc_summary/` | 各阶段 TSV 质控汇总 |
| `09_logs/` | 集群作业日志和渲染后的任务脚本 |

运行前应设置：

```bash
source config/project.env
```

其中 `PROJECT` 指向数据项目，`SNMAR_SCRIPT_ROOT` 指向本仓库的 `03_scripts`。

## 2. DNA 条形码质控与拆分

目录：`03_scripts/01_demultiplex/`

| 代码 | 主要输入 | 主要产出及内容概括 |
|---|---|---|
| `01_config.sh` | 环境变量、DNA 原始目录、T7/T5/I7/I5 表 | 导出拆分目录、QC 目录、barcode 表和运行参数；不直接生成数据 |
| `02_setup_project_dirs.sh` | `01_config.sh` | 创建 `04_fastq_split/`、`08_qc_summary/01_demultiplex/`、日志目录；校验核心脚本和索引表 |
| `03_discover_fastq_pairs.py` | DNA 四个测序路径下的 `*_1.fq.gz`/`*_2.fq.gz` | `pairs.tsv`、`pairs_undetermined.tsv`；记录样本、lane、R1/R2 路径和配对状态 |
| `04_barcode_qc_demultiplex.py` | 一对 DNA FASTQ、T7/T5/I7/I5 白名单、运行模式 | 每对 reads 的 barcode 计数/命中统计；write 模式输出 assigned/unknown FASTQ，并在 read header 保存 CB/CN/XD 等标签 |
| `05_merge_demultiplex_stats.py` | 每个 FASTQ pair 的统计 TSV/JSON | `*_summary.tsv`、`*_per_pair.tsv`、`*_top_unknown_barcodes.tsv`；汇总严格命中率、rescue 命中率和未知 barcode |
| `06_run_demultiplex.sh` | `pairs.tsv`、配置、模式参数（probe/full/write） | 统一调用发现、拆分和汇总程序；生成对应模式的 QC 目录及 FASTQ |
| `07_verify_install.py` | 仓库脚本、索引表、项目目录 | 安装完整性报告；检查文件是否齐全、路径和索引条数是否符合预期 |
| `09_submit_probe_32core.csub` | 少量 DNA pair | Probe 统计与小规模结果，用于在全量前检查文库结构 |
| `10_submit_full_stats_64core.csub` | 全部 DNA pair | 全量只统计不写 FASTQ的 barcode 命中结果 |
| `11_submit_split_exact_32core.csub` | 全部 DNA pair | 严格匹配拆分 FASTQ；主分析只接受 `XD=0` reads |
| `12_submit_split_rescue_32core.csub` | 全部 DNA pair | 支持记录 rescue/mismatch 的拆分结果；后续 DNA fastp 再按 `XD=0` 提取主分析 reads |

小型资源：

| 位置 | 内容 |
|---|---|
| `index/T7.current96.tsv` | 当前 96 个 T7 barcode |
| `index/T5.tsv` | T5 barcode 表 |
| `index/I7.tsv` | I7 barcode 表 |
| `index/I5.tsv` | I5 barcode 表 |
| `reference/00_T7_VALIDATION.txt` | 本批 T7 与旧表一致性的核验记录 |

主输出：`04_fastq_split/write_rescue/` 和 `08_qc_summary/01_demultiplex/`。虽然目录名保留 `write_rescue`，后续主分析由 `XD=0` 强制限定为严格匹配 reads。

- WCG converted fraction 在本流程中定义为内源甲基化信号。
- GCH converted fraction 定义为 GpC 酶标记的开放性信号。
- GCG 不进入两类信号。
- `coverage.bw` 是 PCR 去重后 template calls；`covered_cells.bw` 是覆盖该位点的细胞数；`fraction.bw` 是位点信号比例。
- RNA 和 DNA 的 cell axis 当前独立，最终 modality summary 不强制一一配对。

## 24. RNA exon-supported salvage（步骤 111–121）

该分支针对标准 RNA GeneFull 矩阵深度不足和物种标签异常进行分层审计，重新统计唯一比对、exon overlap、splice junction 和 exact UMI 证据，并单独生成不覆盖正式矩阵的探索性 RNA UMAP。

| 步骤 | 功能 |
|---|---|
| 111–112 | 对 read 层与 UMI 层物种标签进行审计，保留 ambiguous/no-signal 类别 |
| 113–117 | 4 个并行作业重算 exon/gene/splice 支持并汇总 |
| 118–119 | 构建独立 exon-supported salvage 矩阵 |
| 120–121 | 生成低深度探索性 UMAP 和坐标 |

该分支输出不替换步骤 46–61 的正式 RNA 矩阵。结果受低拆分率、低深度和非特异性捕获影响，只能用于诊断数据是否仍保留表达结构。方法背景见 `docs/RNA物种标签审计与DNA_TSS_UMAP计划.md`。

## 26. 同源 100 kb 方法试验（步骤 135–146）

该分支通过 chain/ortholog 坐标构建 human/pig 共享 100 kb 特征轴，过滤两物种支持不足的特征，并导出 Seurat 可读矩阵。其目标是降低 reference-aware UMAP 中物种参考序列差异的贡献，从而更接近“仅按甲基化/开放性特征聚类”的检验。

该分支属于方法试验，不能在未完成服务器全量输出和生物学核验前标记为最终结果。详细参数见 `docs/DNA同源100kb_Seurat试验_步骤135-146.md`。
